- [x] **Home page activation guard (single instance on startup)**
  - Ensure the CVI Home Page opens on extension activation only if an instance is not already open.
  - Avoid creating duplicate tabs or bringing focus redundantly if already active/open.

- [x] **Recent Workspaces & Projects list**
  - Implement a "Recent" section or quick-pick list for workspaces (`.cws`) and projects (`.prj`).

- [x] **Project Tree View improvements: Native CVI layout & ordering**
  - Mirror the native LabWindows/CVI project tree behavior:
    - Eliminate automatic disk/synthetic folder hierarchies.
    - Support user-defined virtual folders and manual reordering of folders and files matching native CVI semantics.
    - Preserve and synchronize the exact folder and file order within the `.prj` file.
    - Combine this faithful CVI-style structure with modern tree view capabilities (drag-and-drop reordering, badges, quick filtering, contextual actions, multi-select).
    - Contextual menu option "Show Full Pathnames" with checkmark toggle to display full paths vs file names.

- [x] **Streamline and rationalize the "CVI Actions" view**
  - Many rows currently only show read-only status (e.g., Target Type, Build Mode, Command Line, Working Directory, Environment).
  - Make these rows interactive/clickable:
    - Clicking *Build mode* triggers mode selection (`labwindowsCvi.selectBuildMode`).
    - Clicking *Target type* opens target configuration or switches target type (`labwindowsCvi.selectTargetType`).
    - Clicking *Command line* / *Working directory* / *Environment* prompts for input directly (`quickActions.edit...`).
    - Clicking *Build steps* and *Dependencies* opens CVI Project Settings directly focused on the corresponding tabs.
  - Consolidate and declutter redundant action items.

- [x] **Evaluate removal of "Safe Mode" options**
  - Review the necessity of "Project Build Settings (Safe Mode)" and related safe-mode fallbacks across the extension.
  - Determine if modern VS Code webview reliability and native fallbacks make safe mode obsolete, and remove or replace it with a cleaner alternative if feasible.
  - *Result:* Safely removed obsolete QuickPick-based Safe Mode fallbacks across the extension.

- [ ] **Completamento delle Build options**

## Major Architecture & Feature Roadmap

- [ ] **Native compilation using individual toolchain components (Makefile engine)**
  - Transition away from executing heavy batch scripts generated by CVI.
  - Formulate a clean, maintainable `Makefile` (or modern build system model) that orchestrates the individual CVI compiler, linker, and resource compiler components directly.
  - Encapsulate all flags, includes, pre/post-build steps, and dependencies in a transparent, reproducible build workflow.

- [ ] **UIR (User Interface Resource) Editor**
  - Research feasibility and architecture of a custom UIR editor inside VS Code.
  - **Reverse Engineering**: Analyze binary `.uir` file structure and/or round-trip translation with `.uir` / `.h` code generation.
  - Formulate scope: inspector, visual editor, or code-synchronized UI resource tool.

- [ ] **Gestione dei file di installazione per la generazione di installer MSI e NI Package Manager**
  - Gestione, parsing e configurazione dei file di distribuzione e installazione CVI (`.cds` / distribution settings).
  - Supporto per la compilazione e generazione automatizzata di installer Windows (`.msi`) e pacchetti per NI Package Manager (`.nipkg`).
