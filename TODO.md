## Major Architecture & Feature Roadmap

- [ ] **Native compilation using individual toolchain components (Makefile engine)**
  - Transition away from executing heavy batch scripts generated by CVI.
  - Formulate a clean, maintainable `Makefile` (or modern build system model) that orchestrates the individual CVI compiler, linker, and resource compiler components directly, performing all build steps.
  - Encapsulate all flags, includes, pre/post-build steps, and dependencies in a transparent, reproducible build workflow.
  - *Initial implementation phase:* Implement this feature as a selectable alternative alongside the default `Compile.exe` driver, enabling side-by-side verification and fallback before considering complete deprecation.

- [ ] **Evaluate compilation with alternative compilers**
  - Assess feasibility, architecture, and requirements to support compiling LabWindows/CVI projects with compilers other than the default CVI toolchain (e.g., Clang, GCC/MinGW, MSVC)
  
- [ ] **UIR (User Interface Resource) Editor**
  - Research feasibility and architecture of a custom UIR editor inside VS Code.
  - **Reverse Engineering**: Analyze binary `.uir` file structure and/or round-trip translation with `.uir` / `.h` code generation.
  - Formulate scope: inspector, visual editor, or code-synchronized UI resource tool.

- [ ] **Distribution & installer generation management (MSI & NI Package Manager)**
  - Parse, manage, and configure LabWindows/CVI distribution and installer specification files (`.cds` / native distribution settings).
  - Support automated building and packaging of Windows Installer packages (`.msi`) and NI Package Manager packages (`.nipkg`).

- [ ] **Remote debugging support**
  - Research and architect remote debugging capabilities for LabWindows/CVI targets deployed on remote machines or headless test benches.
  - Support remote GDB connection (e.g., `gdbserver` over TCP/IP or SSH) with configurable target host/port and path mapping for source and symbols.
